## Model Strategy and Priority

This module has two model tracks that consume the same Egypt agricultural-cycle dataset:

1. **Priority-1 production candidate:** LightGBM/CatBoost agricultural-cycle classifier.
2. **Research/advisory candidate:** SITS-BERT-style Transformer over cycle-level satellite time series.

The Transformer is **not automatically promoted**. It remains advisory/research until it beats the classical ML baseline on:

- active precision
- false-active rate
- macro F1
- cycle/timeline quality
- calibration quality

Phase 1/2 models are Sentinel-2-only. Phase 3 adds the second model generation: `farmtrust-activity-s1s2-v2`, a Sentinel-1 + Sentinel-2 multimodal model.

## Agricultural-Cycle Windowing

Model sequences are split by **Egypt agricultural cycles**, not by calendar years, not by the full historical range, and not by the last 64 observations only.

The expected cycle window comes from `configs/egypt_agricultural_cycles.yaml`. The final detected activity dates are refined dynamically from the satellite signal.

Each prediction should keep both concepts:

## Feature Specification

### Input to the S2 activity models

The sequence builder reads `ndvi_smoothed.csv`, `quality_metrics.json`, `run_metadata.json`, and the Egypt agricultural-cycle calendar. It builds one sequence per AOI per agricultural cycle.

### Per-observation features

| Feature | Source column | Notes |
|---|---|---|
| `ndvi` | `ndvi_smoothed` | Primary vegetation signal |
| `evi` | `evi_smoothed` | Confirmation signal |
| `ndmi` | `ndmi_smoothed` | Moisture |
| `ndwi` | `ndwi_smoothed` | Wetness |
| `bare_soil_proxy` | computed: `((ndmi - ndvi) / (ndmi + ndvi + 1e-6))` | Index-based proxy only; **not true spectral BSI** |
| `valid_fraction` | `valid_fraction` | Observation quality weight |
| `doy_sin` | computed: `sin(2π × doy / 365)` | Cyclical day-of-year |
| `doy_cos` | computed: `cos(2π × doy / 365)` | Cyclical day-of-year |
| `observation_gap_days` | computed from timestamp diff | Irregular sampling signal |
| `is_usable` | `is_usable` | Quality flag (bool → float) |

**Base per-observation features: 10**

> `bare_soil_proxy` is intentionally renamed from `bsi`. It is not true spectral Bare Soil Index because the current preprocessing artifact does not expose raw SWIR/Red/NIR/Blue bands. True BSI can be added later if raw Sentinel-2 band artifacts are added.

### Parcel reliability features

Because FarmTrust parcels are often under 0.5 ha, every model must also receive parcel/data reliability information.

Minimum reliability features:

- `area_ha`
- `estimated_s2_pixel_count`
- `valid_observation_count`
- `mean_valid_fraction`
- `gap_ratio`
- `max_gap_days`
- `geometry_compactness`
- `small_parcel_flag`
- `mixed_pixel_risk`

For LightGBM/CatBoost, these are cycle-level tabular features. For SITS-BERT v0.1, reliability features may be repeated across timesteps. A later SITS-BERT version may use a separate metadata MLP branch.

### Sequence format

- Sort by timestamp ascending.
- Keep only `is_usable = true` rows.
- Split observations by Egypt agricultural-cycle windows.
- Use calendar windows as expected windows, then allow dynamic satellite signal detection to refine actual start/end dates.
- Max sequence length: **64 observations per agricultural cycle**. Pad shorter cycle sequences left with zeros.
- Attention mask: `1` for real observations, `0` for padding.
- DOY sequence: integer day-of-year per timestep, `0` for padding.
- Do not truncate the full AOI history to the last 64 observations. One AOI can produce many cycle sequences.

### Two-stage satellite design

- `farmtrust-activity-s2-v1`: Sentinel-2/index-only model.
- `farmtrust-activity-s1s2-v2`: later Sentinel-1 + Sentinel-2 multimodal model.

## Label Specification

| Label | Integer | Meaning |
|---|---|---|
| `active` | 0 | Vegetation activity window confirmed |
| `bare` | 1 | Below floor, no activity signal |
| `sparse` | 2 | Weak signal, not enough for active |
| `uncertain` | 3 | Insufficient evidence |
| `no_label` | -1 | Unlabeled (ignored in loss) |

### Asymmetric cost rule (SACRED)

False active (predicting `active` when land is bare/fallow) is **always worse** than false inactive.

Use two active thresholds:

- `P(active) >= 0.80` → `confirmed_active` / `confirmed_agricultural_activity`
- `0.65 <= P(active) < 0.80` → `possible_active` / `possible_agricultural_activity`
- `P(active) < 0.65` → not confirmed as active

Do **not** treat active class weight `2.5×` as sacred. The first default training run uses no class weights:

```python
class_weights = [1.0, 1.0, 1.0, 1.0]  # active, bare, sparse, uncertain
```

Then run loss/weight experiments and select by manual validation metrics:

```python
loss_experiments = {
    "no_weights": [1.0, 1.0, 1.0, 1.0],
    "balanced_from_data": "auto",
    "business_risk": [1.0, 1.5, 1.2, 0.8],
    "active_heavy": [2.5, 1.0, 1.2, 0.8],
}
```

### False-active gates (SACRED — never bypass)

A predicted `confirmed_active` window is **downgraded to `possible_active` or `uncertain`** if ANY of these fail:

1. Mean P(active) in window < 0.80 for confirmed active.
2. Mean P(active) in window < 0.65 for possible active.
3. Fewer than 3 consecutive observations above threshold.
4. Window duration < 15 days.
5. Mean NDVI in window < 0.18 (existing `LOW_VEGETATION_FLOOR` from T-05).
6. Mean valid_fraction in window < 0.40.
7. Parcel reliability gate fails for small parcel / mixed-pixel / long-gap risk.

### Lender-facing decision mapping

Keep internal ML labels simple: `active`, `bare`, `sparse`, `uncertain`. API/artifact output must also include lender-safe fields:

- `ml_lender_decision`
- `ml_false_active_risk`
- `ml_review_recommendation`

Mapping:

- `P(active) >= 0.80` and gates pass → `confirmed_agricultural_activity`, false-active risk `low`
- `0.65 <= P(active) < 0.80` and gates pass → `possible_agricultural_activity`, false-active risk `medium`
- `bare` highest probability → `no_agricultural_activity_detected`
- `sparse` highest probability → `weak_or_sparse_vegetation`
- `uncertain` highest probability or gates fail → `insufficient_evidence`

## Weak Label Strategy

The `weak_labeler.py` generates training labels from the **existing rule-based pipeline outputs** — specifically `season_windows.json` and `ndvi_smoothed.csv`. This is the correct approach: we trust the existing T-03/T-04/T-05 pipeline as a weak supervision source.

### Weak label assignment rules

For each usable observation in `ndvi_smoothed.csv`:

1. If the timestamp falls **inside** a detected activity window (`season_windows.json`) with `quality_label = "good"` and `confirmation_level` in `["strong", "moderate"]`:
   → `label = active`, `weak_confidence = 0.80`

2. If the timestamp falls **inside** a detected activity window with `quality_label = "weak"` or `confirmation_level = "weak"`:
   → `label = sparse`, `weak_confidence = 0.60`

3. If `ndvi_smoothed < 0.18` (existing `LOW_VEGETATION_FLOOR`) AND the timestamp is **not** inside any activity window AND `valid_fraction >= 0.90`:
   → `label = bare`, `weak_confidence = 0.75`

4. If the timestamp falls in a **long gap window** (`long_gap_windows` from `quality_metrics.json`):
   → `label = uncertain`, `weak_confidence = 0.40`

5. Everything else:
   → `label = uncertain`, `weak_confidence = 0.50`

> These are NOISY labels. Use label smoothing = 0.1 during training. Never treat weak labels as ground truth.

### Manual validation, sacred test set, and active learning

Weak labels are for scale, not for final proof. The ML workflow must use:

| File | Purpose |
|---|---|
| `data/ml/labels/weak_labels.csv` | initial training / pretraining labels |
| `data/ml/labels/manual_validation.csv` | model selection, threshold tuning, loss/weight experiments |
| `data/ml/labels/test_set.csv` | sacred final evaluation only; never train/tune on it |
| `data/ml/labels/annotation_queue.csv` | active-learning queue for human review |

Prioritize annotation for: possible-active predictions, rule/model disagreements, low-confidence active predictions, parcels under 0.5 ha, high mixed-pixel risk, high-value lender parcels, and long cloud-gap cases.

#### 1.2 — `farmtrust_core/ml/sequence_builder.py`

```python
"""
Builds agricultural-cycle input tensors from existing preprocessing artifacts.

Reads:
    data/preprocess/<aoi_id>/ndvi_smoothed.csv
    data/preprocess/<aoi_id>/quality_metrics.json
    data/<aoi_id>/run_metadata.json
    configs/egypt_agricultural_cycles.yaml

Produces:
    dict with keys:
        features:        np.ndarray shape (N_cycles, 64, 10) float32
        attention_mask:  np.ndarray shape (N_cycles, 64)     bool
        doy:             np.ndarray shape (N_cycles, 64)     int16
        timestamps:      list[list[str]]                    ISO date strings
        cycle_metadata:  list[dict]                         cycle_id, expected window
        aoi_id:          str
        usable_count:    int
"""

import numpy as np
import pandas as pd
from pathlib import Path
import logging

logger = logging.getLogger(__name__)

MAX_SEQ_LEN = 64
FEATURE_NAMES = [
    "ndvi", "evi", "ndmi", "ndwi", "bare_soil_proxy",
    "valid_fraction", "doy_sin", "doy_cos",
    "observation_gap_days", "is_usable_float"
]

class SequenceBuilder:
    def __init__(self, data_root: str = "data", calendar_path: str = "configs/egypt_agricultural_cycles.yaml"):
        self.data_root = Path(data_root)
        self.calendar_path = Path(calendar_path)

    def build(self, aoi_id: str) -> dict:
        """
        Build one padded sequence per Egypt agricultural cycle.

        Important:
        - Do NOT keep only the latest 64 observations for the whole AOI.
        - Split by expected agricultural cycles first.
        - Each cycle is padded/truncated independently to MAX_SEQ_LEN.
        - Dynamic signal detection later refines the detected activity window inside each expected cycle.
        """
        smoothed_path = self.data_root / "preprocess" / aoi_id / "ndvi_smoothed.csv"
        assert smoothed_path.exists(), f"Missing: {smoothed_path}"

        df = pd.read_csv(smoothed_path, parse_dates=["timestamp"])
        df = df[df["is_usable"] == True].copy()
        df = df.sort_values("timestamp").reset_index(drop=True)
        assert len(df) > 0, f"No usable observations for {aoi_id}"

        df["doy"] = df["timestamp"].dt.dayofyear
        df["doy_sin"] = np.sin(2 * np.pi * df["doy"] / 365.0)
        df["doy_cos"] = np.cos(2 * np.pi * df["doy"] / 365.0)
        df["bare_soil_proxy"] = (df["ndmi_smoothed"] - df["ndvi_smoothed"]) / \
            (df["ndmi_smoothed"] + df["ndvi_smoothed"] + 1e-6)
        df["observation_gap_days"] = df["timestamp"].diff().dt.days.fillna(0).clip(0, 90)
        df["is_usable_float"] = 1.0

        feature_cols = [
            "ndvi_smoothed", "evi_smoothed", "ndmi_smoothed", "ndwi_smoothed",
            "bare_soil_proxy", "valid_fraction", "doy_sin", "doy_cos",
            "observation_gap_days", "is_usable_float"
        ]

        # Claude Code: implement load_egypt_cycles() in calendar.py.
        # It should return expected cycle windows for every year covered by df.
        cycles = load_egypt_cycles(self.calendar_path, df["timestamp"].min(), df["timestamp"].max())

        cycle_features, cycle_masks, cycle_doy, cycle_timestamps, cycle_metadata = [], [], [], [], []

        for cycle in cycles:
            cdf = df[(df["timestamp"] >= cycle["start_date"]) & (df["timestamp"] <= cycle["end_date"])].copy()
            if len(cdf) == 0:
                continue

            raw = cdf[feature_cols].values.astype(np.float32)
            doy_raw = cdf["doy"].values.astype(np.int16)
            ts_raw = cdf["timestamp"].dt.strftime("%Y-%m-%d").tolist()

            # Pad/truncate inside this cycle only. Never truncate the whole AOI history.
            if len(raw) >= MAX_SEQ_LEN:
                raw = raw[-MAX_SEQ_LEN:]
                doy_raw = doy_raw[-MAX_SEQ_LEN:]
                ts_raw = ts_raw[-MAX_SEQ_LEN:]
                mask = np.ones(MAX_SEQ_LEN, dtype=bool)
            else:
                pad = MAX_SEQ_LEN - len(raw)
                raw = np.vstack([np.zeros((pad, len(FEATURE_NAMES)), dtype=np.float32), raw])
                doy_raw = np.concatenate([np.zeros(pad, dtype=np.int16), doy_raw])
                ts_raw = [""] * pad + ts_raw
                mask = np.concatenate([np.zeros(pad, dtype=bool), np.ones(len(cdf), dtype=bool)])

            cycle_features.append(raw)
            cycle_masks.append(mask)
            cycle_doy.append(doy_raw)
            cycle_timestamps.append(ts_raw)
            cycle_metadata.append(cycle)

        return {
            "features": np.stack(cycle_features),
            "attention_mask": np.stack(cycle_masks),
            "doy": np.stack(cycle_doy),
            "timestamps": cycle_timestamps,
            "cycle_metadata": cycle_metadata,
            "aoi_id": aoi_id,
            "usable_count": len(df),
        }
```

```
SITSBertEncoder:
    - Linear input projection: input_dim(10) → hidden_size(256)
    - DOY positional encoding: sinusoidal on doy/365, added to projected input
    - Transformer encoder: 3 layers, 8 heads, hidden=256, ff=512
    - Padding mask from attention_mask (True = ignore in attention)
    - Output: (batch, seq_len, hidden_size)

SITSBertPretraining(SITSBertEncoder):
    - Reconstruction head: Linear(256, 10)
    - Loss: MSE on masked positions only

SITSBertFinetune(SITSBertEncoder):
    - Classification head: Linear(256, 4)
    - Loss: WeightedCrossEntropy with default class_weights=[1.0,1.0,1.0,1.0], ignore_index=-1, label_smoothing=0.1; additional class-weight experiments are selected by manual validation
    - get_attention_weights(): return attention weights from last layer for interpretability
```

## Conflict Avoidance Rules

These were identified from the project scan. Claude Code must respect all of them.

| Rule | Reason |
|---|---|
| Never use field names `season_*` for ML outputs | These are reserved compatibility names in the existing pipeline with documented semantics |
| Never set `valid_fraction >= 0.90` as a hard ML filter | The existing usability gate already handles this upstream; our input is pre-filtered |
| Never interpolate or synthesize timestamps | Explicit design decision in T-04; must be preserved in sequence builder |
| `MNDWI` is NOT in `ndvi_smoothed.csv` | It exists at ingestion but is not in the preprocessing contract; do not reference it in ML features |
| Do not call the NDVI/NDMI proxy `bsi` | Use `bare_soil_proxy`; true BSI requires raw bands and is not currently available |
| `land_status` values (`active`, `intermittent`, `inactive`) are existing rule-based outputs | ML uses `ml_land_status` with the same vocabulary but as a separate field |
| Do not import from `farmtrust_core/scoring/rules.py` | ML module must not depend on rule-based scoring internals |
| Do not create a new `api/worker.py` — modify only the existing one | One worker entrypoint is an explicit architecture commitment |
| Do not add ML inference to the synchronous request path | Heavy inference belongs in the background worker, which already runs async |
